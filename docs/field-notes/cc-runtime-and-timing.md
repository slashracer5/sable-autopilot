**Runtime and timing facts for control programs (CC: Tweaked 1.120.2 + Avionics/Sable, measured)**

- **What costs a server tick (0.05 s) - measured live 2026-11-16 (8 calls: sequential 360 ms vs parallel 46 ms):** (a) every peripheral method marked `main` in the signature tables (all setters such as `setShiftLevel`/`setManualTarget`/`setGeneratedSpeed`/`assemble`, and a few reads such as `getSubnetworkAnchorId`), and (b) **every `sublevel.*` call** (`getLogicalPose`, `getLinearVelocity`, `getAngularVelocity`, `getMass`...: 20 calls took 1000 ms, i.e. ~50 ms each, 4 sequential 178 ms vs 49 ms in parallel). Peripheral methods marked `any` (bearing `getSpeed`/`getThrust`/`getManualTarget`, gimbal `getAngles`/`getAngularRates`, transmission `getShiftLevel`, motor `getGeneratedSpeed`...) are **free**: 20 sequential calls took 0-1 ms, also through the wired modem / ship bridge. Issuing the tick-costing calls of one control step together with `parallel.waitForAll(...)` costs **one tick total**: that took a controller from 5 Hz to a steady 20 Hz. Do not bother parallelising plain `any` reads.
- **Parallel idiom**: build `local jobs = {}` of closures, each storing its result into a table, then `parallel.waitForAll(table.unpack(jobs))`. Collect results by closure, not by return value.
- **Yielding calls stall while the game is paused or the window is unfocused** (singleplayer pauses on focus loss / menus). A call can then appear to hang or time out and succeed instantly on retry. Keep Minecraft focused during hardware tests and flights; after a relay timeout, `cc_cancel` and retry before suspecting the code.
- **A pure ~0.2 s delay** separates a command from the ship's physical response. Size loop gains and crossover (about 1 rad/s attitude, 0.7 rad/s position) for 0.25 s of delay; designing for the 0.1 s loop period oscillated.
- **Lua limits that bit**: a function may reference at most **60 outer-scope locals/upvalues** (a long program failed to compile with an error naming that limit; put read-only settings in one table `C`). `table.unpack` can be absent in some embeddings; write `local unpack = table.unpack or unpack`.
- **A tight loop that never yields is killed after ~7 s** ("Too long without yielding"). Control loops must yield: `sleep(0)`, a setter / `main`-thread call, or a `sublevel.*` call (plain `any` peripheral getters do NOT yield).
- **Wired modem API on the network**: `peripheral.call(modemSide, "getNamesRemote")`, `"getTypeRemote", name`, `"getMethodsRemote", name`, `"getNameLocal"`, `isWireless`. Remote names are valid directly in `peripheral.call(name, method, ...)` from the computer.
- **`textutils.serialiseJSON`**: fine for plain tables, vectors and numbers; it drops matrix cells (see `sable-sublevel-api`), with `{unicode_strings=true}` it throws on invalid UTF-8 (fall back to byte mode), and JSON `\uXXXX` escapes decode to UTF-8 bytes but surrogate pairs (emoji) decode wrongly. Numbers keep ~17 significant digits.
- **Sensor values at rest are not exactly zero** (1e-6..1e-5): compare with tolerances.
- **Never leave actuators armed on exit**: wrap flight/test code so that a fault, `Ctrl+T` or error path sets transmissions to 0, motors to their original value, and clears manual targets.
